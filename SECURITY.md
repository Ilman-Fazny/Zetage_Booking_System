## 🛡️ Security Policy

| Version | Supported |

## Reporting a Vulnerability

If you discover a security vulnerability within this project, please **do not open a public GitHub issue**. Reporting security flaws publicly risks exposing attendee and booking data before a patch can be applied.

Instead, please report vulnerabilities responsibly using the following process:

### 📨 Where to Report

Send an email to **[ilmanfazny@gmail.com]** with the subject line `[SECURITY VULNERABILITY] - <Brief Description>`.

### 📝 What to Include

To help us triage and resolve the issue quickly, please include:

* A clear description of the vulnerability and its potential impact.
* Step-by-step instructions (or a minimal proof-of-concept script/request payload) to replicate the issue.
* Any details regarding the environment or configurations required to trigger it.

### ⏳ What to Expect

* **Acknowledgement:** You will receive an initial automated or manual confirmation email within **24 to 48 hours** of submission.
* **Status Updates:** Our development team will investigate the report. You can expect a progress update or clarification requests every **3 to 5 business days**.
* **Resolution:** If the vulnerability is accepted, we will coordinate a fix and release a patched version. We will credit you for the discovery in our release notes if desired. If the report is declined or determined to be an intended behavior/non-issue, we will provide a detailed technical explanation of our reasoning.
